## Required metadata
Where relevant, every substantive numbered document records:
- title;
- stable DOC ID;
- status;
- domain/program owner;
- authority/evidence class;
- scope or ownership;
- upstream dependencies;
- downstream consumers.

## Required substantive fields
A substantive document should also state:
- what it owns;
- what it does not own;
- current confirmed state;
- target state;
- delta;
- unknowns/conflicts;
- migration impact when applicable;
- acceptance/verification;
- revision trigger;
- next unresolved action.

## Exceptions
Indexes, manifests, and tiny control records may omit fields that add no operational value, but omissions must not hide authority or ownership.

## Acceptance
A future session can identify what the file controls, why it exists, and what depends on it without using chat memory.

## Revision trigger
Change if the documentation acceptance standard changes mandatory metadata.

## Next action
