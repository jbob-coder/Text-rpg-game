## 1. Purpose

Define the smallest future proof for persistent adversary/world-memory behavior without forcing the Phase 1 Service Tunnel contacts to become named recurring enemies.

This packet is deliberately conservative.

## 2. Current canon boundary

Current Gate Twelve content confirms:
- fresh boot prints in Service Tunnel;
- unknown activity below/around restricted infrastructure;
- directional trace pointing deeper;
- no canonical named hostile faction or persistent enemy identity in the current vertical slice.

Therefore this packet does **not** invent a final named rival.

## 3. Candidate source

After the proposed Service Tunnel tactical encounter is implemented, one surviving encounter-local contact may become an **eligibility candidate**.

Candidate encounter-local IDs are owned by that encounter packet.

Promotion requires later canon approval.

Default behavior:
- contacts remain encounter-local and do not persist.

## 4. Proof promotion gate

To promote one contact:
1. encounter resolves with the contact alive and not permanently removed;
2. content explicitly marks that individual as important enough to recur;
3. assign a new stable persistent NPC/adversary ID;
4. create identity/profile record;
5. migrate only perceived memories/knowledge/injury;
6. assign lifecycle/current location;
7. record eligibility source event.

No promotion occurs automatically because the contact survived.

## 5. Minimum durable memory

The promoted actor should remember one meaningful encounter fact, such as:
- Jack used a visible tactic;
- Jack spared/captured/injured them;
- Tamsin was present;
- they escaped through the deeper route.

The exact memory depends on what they actually perceived.

## 6. One bounded adaptation

The proof requires exactly one traceable adaptation from an authored option set.

Safe candidate examples:
- prefer stronger cover after suffering a ranged attack;
- withdraw earlier after a severe injury;
- avoid a route where they were trapped;
- equip a valid protective item if later faction/item access exists.

No stat inflation.

The final adaptation should be selected only after the encounter/content/faction facts exist.

## 7. Lifecycle

After first encounter:
- active if safely escaped and still available;
- injured/recovering if aftermath says so;
- captured if captured;
- dead if authoritatively killed.

The proof must honor that state.

## 8. World routing

A future recurrence must use a valid Gate Twelve/world route.

Until the public surface/depot components are connected by authoritative content, the actor cannot silently cross that missing graph edge.

## 9. Recurrence scenario

A valid second encounter/event requires:
- lifecycle active;
- sufficient time/recovery;
- route/location eligibility;
- goal/faction reason;
- player/actor world state supporting contact.

The system must also accept “no recurrence yet.”

## 10. Player intel

Before promotion/identification:
- player may know only Unknown Contact plus observed traits.

Later intel may reveal:
- identity/alias;
- visible injury;
- observed changed tactic/equipment;
- last known location;
- rumor.

Hidden goals/adaptation logic remain private.

## 11. Removal scenario

The proof is incomplete unless the same persistent actor can later:
- die;
- be captured/removed;
- retire;
without broken world/quest references or accidental respawn.

## 12. Verification scenario

Future runtime acceptance:
1. complete first encounter;
2. explicitly promote eligible survivor;
3. save;
4. reload;
5. verify identity/lifecycle/memory;
6. apply one bounded adaptation;
7. advance world state/time;
8. recurrence query returns actor only when valid;
9. player-safe intel exposes only known facts;
10. permanently remove actor;
11. save/reload;
12. prove no recurrence and no reference corruption.

## 13. Phase 1 relationship

Phase 1 does not require this system to ship.

The Phase 1 tactical encounter is allowed to use encounter-local contacts only.

This V09 proof exists so later expansion can add persistent enemies without redesigning identity, memory, routing, save, or privacy contracts.

## 14. Result

The Gate Twelve proof target is defined without selecting or naming a canonical recurring adversary.

That decision remains future content/canon work.
