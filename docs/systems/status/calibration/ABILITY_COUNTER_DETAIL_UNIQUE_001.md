## COUNTER_UNQ_001 — Origin Key

Natural limitations:
- requires a real compatible Status endpoint/layer;
- authentication is not the same as permission;
- child-function prerequisites remain authoritative;
- safeguards can restrict scope;
- interpretation is not omniscient;
- Focus/Resolve/system strain limit repeated or deep access.

Counter/denial routes:
- endpoint absent;
- layer outside Origin Key's allowed authentication scope;
- safeguard denial;
- unmet child prerequisite;
- read-only permission;
- session expiration;
- insufficient resources;
- incomplete knowledge of what exposed metadata means.

System architecture pressure:
A dormant function can remain inaccessible even after authentication if its own requirements are not satisfied.

Failure condition:
The design fails if Origin Key:
- creates permissions from nothing;
- copies arbitrary powers;
- exposes all hidden information;
- edits Status freely;
- ignores safeguards;
- permits duplicate Unique holders;
- bypasses Level-100/Unique ontology without documentation.

# Acceptance gate

Unique counterplay is primarily **permission and architecture boundedness**, not rarity-versus-rarity combat resistance.
