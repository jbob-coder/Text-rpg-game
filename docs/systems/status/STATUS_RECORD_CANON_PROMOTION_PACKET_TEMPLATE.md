## 2. Proposed decision

Choose one:
- `APPROVE_CANON`
- `APPROVE_WITH_OPEN_NUMERIC_FIELDS`
- `RETURN_FOR_REFINEMENT`
- `REJECT`
- `DEPRECATE_WITH_ID_RESERVED`

State exactly what is being approved.

## 3. Governing-law check

Document:
- governing system standard;
- mechanic's core law;
- explicit forbidden behaviors;
- known edge cases;
- unresolved child rules.

A record cannot be promoted by name/summary alone.

## 4. Identity and overlap check

Document:
- nearest adjacent mechanics;
- why this record remains distinct;
- same-resolver overlaps;
- cross-family/cross-tier conflicts;
- whether any existing record should be deprecated instead.

## 5. State ownership

Document:
- conceptual authoritative owner;
- read dependencies;
- write target;
- qualification/evidence owner;
- save persistence;
- player-safe projection.

Runtime module mapping may remain `TBD` if implementation is not yet authorized.

## 6. Numeric readiness

Record:
- required numeric parameters;
- unit/band;
- candidate value/range if approved;
- hard caps/floors;
- calibration evidence;
- sensitivity/risk.

A canon law may be approved with explicit `TBD` numeric fields only if those values are not needed to define the identity of the mechanic.

## 7. Knowledge and visibility

Document:
- what the owner knows;
- public knowledge;
- school knowledge;
- government/military/research knowledge;
- faction knowledge;
- classification reason;
- false beliefs/rumors;
- discovery/reveal events;
- provenance.

Do not inherit a calibration knowledge template without review.

## 8. World integration

Document:
- training source;
- professions;
- institutions/factions;
- law/regulation;
- economic/strategic significance;
- historical cases;
- regional/time variation.

Use `TBD` rather than inventing named entities that parent world documentation has not established.

## 9. Safety/exploit review

Check:
- self-harm farming;
- save/load duplication;
- trivial repetition;
- hidden-information leakage;
- resource creation;
- authorization bypass;
- identity duplication;
- stacking runaway;
- irreversible-state corruption.

## 10. Test obligations

List:
- unit tests;
- interaction tests;
- save/load tests;
- exploit tests;
- projection/privacy tests;
- migration tests;
- world-content validation.

## 11. Contradictions and unknowns

Separate:
- confirmed contradiction;
- unresolved ambiguity;
- intentional mystery;
- missing numeric calibration;
- missing world integration;
- implementation-only unknown.

No unknown should be silently treated as canon.

## 12. Evidence reviewed

List exact documentation/files reviewed.

For source-derived or historical claims, preserve provenance.

## 14. Post-approval changes

After approval:
- stable ID remains fixed;
- material law changes require a new review;
- deprecated IDs are never reused;
- implementation status remains separate from canon status;
- later numeric tuning must preserve approved mechanic identity unless re-reviewed.

This template is the required shape for future explicit canon promotion. It does not bulk-promote Wave-001 content.
