1. the resolver key becomes the shared composition point;
2. each passive contributes only if its own scope/qualification/context is valid;
3. duplicate ownership is rejected;
4. the combined value respects one hard cap/floor;
5. the final term is committed by its authoritative owner;
6. player UI receives only player-safe result/projection data.

## Ordered-composition rule

For `ORDERED_STAGE_COMPOSITION`:
- upstream information/familiarity/decision effects resolve first;
- downstream execution/resource/recovery effects resolve afterward;
- a bonus at one stage cannot be re-applied as a second bonus at another stage.

## Distinct-stage rule

For `DISTINCT_STAGE_NO_SHARED_TERM`:
- retain the pair as an interaction test;
- do not create a shared numeric resolver;
- each state owner commits only its own term.
