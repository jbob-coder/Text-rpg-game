Purpose: define qualitative scenario anchors for the 20 canonical shared passive resolvers before any coefficient, scale, probability model, or final unit value is selected.

This document deliberately does **not** assign final numbers.

## Anchor vocabulary

Each resolver uses four scenario anchors:

- `BASELINE` — valid ordinary case with no passive contribution.
- `FAVORABLE` — context where the underlying task is easier or strongly supported.
- `ADVERSE` — context where the same valid resolver faces materially greater difficulty.
- `BOUNDARY` — condition that must remain impossible, unavailable, capped, or separately resolved regardless of passive strength.

The anchors describe relationships. They are not numeric bands.

## RESOLVER_KNOWN_INFORMATION_RECALL

Base term:
retrieval burden/error for one already-acquired datum.

Unit class:
`ERROR_BURDEN`.

### BASELINE
Character attempts to recall information that was legitimately learned and reinforced under ordinary pressure.

### FAVORABLE
Information was recently used, strongly reinforced, highly familiar, or supported by an appropriate domain-specific memory passive.

### ADVERSE
Information is old, weakly reinforced, contextually similar to competing information, or recalled under significant but non-catastrophic pressure.

### BOUNDARY
Information was never acquired or is outside the character's authorized/known information set.

Passive effects may reduce retrieval burden but cannot create the datum.

## RESOLVER_AUDITORY_SOURCE_SEPARATION

Base term:
source-separation error for available auditory input.

Unit class:
`ERROR_BURDEN / INTERPRETATION_CONFIDENCE`.

### BASELINE
Two or more audible sources overlap but remain physically detectable.

### FAVORABLE
Strong signal-to-noise separation, familiar source signatures, stable listening position.

### ADVERSE
Crowded acoustic environment, masking noise, reverberation, unfamiliar source signatures.

### BOUNDARY
Signal is absent, fully inaudible, outside sensory capability, or intentionally inaccessible.

Passives may improve separation of available input, not generate sound information.

## RESOLVER_ENGAGEMENT_DISTANCE_JUDGMENT

Base term:
spacing-estimation error for observed target/equipment geometry.

Unit class:
`ERROR_BURDEN / DISTANCE`.

### BASELINE
Observed target and familiar equipment are in clear geometry with ordinary movement.

### FAVORABLE
Known weapon/reach profile, clear line of sight, stable terrain, repeated practice.

### ADVERSE
Moving target, cluttered terrain, unusual elevation, unfamiliar reach profile.

Physical reach, actual distance, and collision geometry remain authoritative.

No passive extends a weapon or body simply by improving judgment.

## RESOLVER_IMMEDIATE_THREAT_PRIORITIZATION

Base term:
prioritization error/burden among already recognized immediate threats.

Unit class:
`ERROR_BURDEN`.

### BASELINE
Several visible/recognized threats differ in urgency.

### FAVORABLE
Threats match familiar tactical patterns and available information is clear.

### ADVERSE
Multiple simultaneous threats, conflicting objectives, incomplete but legitimate observations, time pressure.

Passive effects improve ordering, not omniscience.

## RESOLVER_PROCEDURE_COMPLIANCE_ERROR

Base term:
omission/error burden for one known authorized procedure step/check.

Unit class:
`ERROR_BURDEN`.

### BASELINE
Character performs a familiar valid procedure in an ordinary working context.

### FAVORABLE
Clear documentation, familiar tools, stable environment, recently practiced procedure.

### ADVERSE
Long procedure, interruption pressure, unfamiliar local variation, multiple required checks.

### BOUNDARY
Missing authorization, missing knowledge, invalid procedure version, or impossible task cannot be corrected by passive compliance bonuses.

Gate Twelve evidence can later supply local maintenance/archive procedure examples, but current local documentation does not yet define exact procedure rules.

## RESOLVER_PROLONGED_FOCUS_DRAIN

Base term:
base Focus loss over an eligible sustained task interval.

Unit class:
`RESOURCE_RATE`.

### BASELINE
Valid prolonged reasoning, calibration, negotiation, vigilance, or professional task.

### FAVORABLE
Familiar task, appropriate rest, low interruption load, supportive work conditions.

### ADVERSE
Long duration, sustained precision demand, high distraction load, demanding social/technical context.

### BOUNDARY

The authoritative Focus maximum/minimum remains outside this passive resolver.

## RESOLVER_STAMINA_RECOVERY_OPPORTUNITY

Base term:
base Stamina restored during one valid recovery transaction.

Unit class:
`RECOVERY_EFFECT / RESOURCE_AMOUNT`.

### BASELINE
A legitimate recovery opportunity exists after ordinary exertion.

### FAVORABLE
Safe rest context, valid recovery window, no major interfering condition.

### ADVERSE
Heavy recent exertion, incomplete rest, minor conditions, constrained recovery context.

### BOUNDARY
No passive creates a recovery opportunity that does not exist, exceeds Stamina maximum, or bypasses an active blocking condition.

One recovery transaction is resolved once even when multiple passives qualify.

## RESOLVER_SLEEP_RESTORATION

Base term:
resource/state restoration from one valid adequate-sleep interval.

Unit class:
`RECOVERY_EFFECT / RESOURCE_AMOUNT`.

### BASELINE
Character receives an adequate valid sleep interval.

### FAVORABLE
Safe environment, good sleep quality, low interruption, normal recovery conditions.

### ADVERSE
Interrupted but still valid sleep, uncomfortable environment, recent heavy exertion.

### BOUNDARY
Severe sleep deprivation does not become safe, and a sleep passive cannot convert an inadequate interval into full rest unless a separate rule explicitly allows it.

## RESOLVER_POST_EVENT_EMOTIONAL_RECOVERY

Base term:
recovery toward functional baseline after a resolved emotional event.

Unit class:
`RECOVERY_EFFECT / PERFORMANCE_DECAY`.

### BASELINE
A meaningful emotional/social event has ended and recovery is legitimately possible.

### FAVORABLE
Safe environment, trusted support, familiar coping/recovery process, adequate time.

### ADVERSE
High-intensity event, repeated recent stress, limited recovery environment.

### BOUNDARY
The resolver cannot erase memory, delete emotion, rewrite relationships, or force immediate normality.

## Cross-resolver scenario rule

When one gameplay situation activates several resolvers:
1. each base term is established independently;
2. scope/eligibility is checked;
3. same-term passive modifiers are composed once through the canonical shared resolver;
4. ordered-stage interactions resolve in documented order;
5. one resolver's favorable anchor does not automatically make another resolver favorable.

## Numeric-entry gate

Before assigning candidate coefficients to any resolver, the parent system must provide:
- authoritative scale/range for its base term;
- ordinary scenario values or test fixtures;
- hard cap/floor meaning;
- save/rounding behavior;
- at least one favorable and one adverse test case.

## Current result

All **20 / 20 canonical passive shared resolvers** now have qualitative baseline, favorable, adverse, and hard-boundary scenario anchors.

This is the final qualitative preparation layer before parent-system ranges and candidate coefficient bands can be introduced.

No passive is canon-promoted and no final numeric value is established by this document.
