## Primary rule

For THE GAME / Text RPG + Pixel Art Stack, this repository is the priority project:

`jbob-coder/Text-rpg-game`

Agents must inspect it before considering other repositories.

## What this project is

This is the text-based/narrative RPG with:
- persistent rules/state;
- Android application;
- player-safe presentation;
- quests/world map;
- stats/equipment/inventory;
- pixel-art scenes, map, characters, items, HUD and overlays.

The Pixel Art Stack is a presentation/asset layer for this game. It is not the Godot Pixel RPG and is not a migration of unrelated prototypes.

## Non-authoritative external projects

Unless explicitly requested by the owner, do not treat these as design/code/canon authority for this repository:
- Godot Pixel RPG projects;
- Monster Choice RPG;
- WorldLife RPG;
- Shooter RPG;
- unrelated Jack Wilson continuities;
- archived prototypes;
- external games used only as inspiration/reference.

External material may inspire high-level structure only after it is rewritten into original project documentation.

## Branch policy

- `main` is not implementation authority.
- Do not merge/promote/rewrite `main` without an explicit promotion decision.
- Documentation and implementation changes should occur on purpose-built branches.
- Old PRs/branches remain historical evidence until formally superseded.
- If a branch is superseded, record the successor rather than deleting evidence.

## Tool and cost restrictions

Default work must remain free/zero-cost where practical.
Do not silently:
- enable paid services;
- use billing-risk GitHub resources;
- use paid external generation;
- publish paid/store releases.

Do not use an unrelated coding/plugin workflow as authority when built-in repository tooling is available.

## Visual restrictions

- final pixel art must be authored/approved visual assets, not placeholder boxes or code geometry;
- use nearest-neighbor/source-native rendering;
- no saturated cyberpunk visual direction unless a future canon decision explicitly changes it;
- do not duplicate assets when reusable modules/layers fit;
- do not invent canonical player/NPC identity details merely to fill missing art;
- references remain reference-only until promoted through the documented asset lifecycle.

## Context preservation

Every substantial documentation or development session must leave:
- branch/HEAD;
- files changed;
- decisions made;
- open gaps;
- evidence actually run;
- next action;
- assumptions that must not be carried forward.

This routing file supersedes any older report that treats another game repository as the default context for THE GAME.
